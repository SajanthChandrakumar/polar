## Shared interface
PatternAnalysis JSON: {days,outcome,from,to,activity_from,activity_to,timezone:'Europe/Zurich',unit:'min'|'ANS',threshold:number|null,status:'available'|'insufficient',minimum_group_size:7,groups:{lower:{count,median:number|null,q1:number|null,q3:number|null},upper:{count,median,q1,q3}},pairs:[{activity_date,outcome_date,steps,value,group:'lower'|'upper',activity_response_ids:string[],outcome_response_ids:string[]}],exclusions:{activity_unavailable:number,activity_provisional:number,outcome_unavailable:number}}. Missing/invalid are combined as unavailable. from/to are outcome dates. Always return all fields, use null not NaN. Suppress all median/q1/q3 if either group<7. Pairs ordered by outcome_date. Pure function calculate_patterns(activity_points,outcome_points,*,days=90,outcome='sleep',now=None); normalized points have date,value,provisional,response_ids. Wrapper patterns(store,days=90,outcome='sleep',now=None) reuses _metric_payloads/_build_values/_day_value via a narrow shared daily-points loader in analytics.py; preserve existing analytics output.
